# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Configurable LLM guardrail (input and output checks: allow, redact, block) plus a benchmark harness that measures its accuracy. Design and implementation plan: `docs/2026-11-12-guardrail-module-design.md` and `docs/2026-11-12-guardrail-module-plan.md`.

## Commands

Run everything from the repo root with the shared Lab venv at `../.venv` (Python 3.12, managed by uv, has no pip). Do not create a local `.venv` in this repo: no `uv venv`, no `uv sync`/`uv run` without `UV_PROJECT_ENVIRONMENT=../.venv` (they create `./.venv`). Dependencies live in `pyproject.toml` + `uv.lock` (groups: core in `dependencies`, `eval`, `dev`); add one with `uv add --no-sync <pkg>` (`--group eval|dev` if it is not core), then sync. Keep `--inexact` so packages of the other Lab repos stay installed.

```sh
../.venv/bin/python -m pytest tests                                   # all tests, no network
../.venv/bin/python -m pytest tests/test_pipeline.py::test_stops_after_first_block
../.venv/bin/ruff check . && ../.venv/bin/ruff format --check .        # ruff defaults, line length 88
UV_PROJECT_ENVIRONMENT=../.venv uv sync --inexact                     # install pyproject.toml + uv.lock

../.venv/bin/python main.py check "text" [--stage output --user-input "q"] [--config config.yaml]
../.venv/bin/python main.py eval --dataset datasets/sample.jsonl [--isolate] [--concurrency 4] [--categories prompt_injection]
../.venv/bin/python main.py compare _workspace/runs/<A> _workspace/runs/<B>
../.venv/bin/python main.py fetch prompt_injections|toxic_chat           # writes datasets/public/<name>.jsonl
./scripts/sync_models.sh                                               # refresh ModelId in core/constants.py
```

`main.py` loads `.env`. Guards of type `embedding` and `llm_judge` need `OPENROUTER_API_KEY` (optional `OPENROUTER_BASE_URL`) unless a client is passed to `load_guardrail`.

## Architecture

`core/` is the production unit: projects copy this folder alone, often under another name such as `guardrail/`. So inside `core/` use relative imports only, never import `eval` or `main`, and keep its dependencies to `pydantic`, `pyyaml`, `httpx`. `core` reads `os.environ` directly and never loads `.env`. `eval/` and `main.py` use only the public API exported from `core/__init__.py`.

Request flow: `load_guardrail(path)` (`core/pipeline.py`) parses YAML with `core/config.py` into `{Stage: [raw params]}`, builds each guard through the registry, and returns a `Guardrail`. `check_input` / `check_output` run that stage's guards strictly in YAML order. A `redact` result replaces the text passed to the next guard. The first `block` stops the pipeline. `decide()` in `core/types.py` merges results into a `Decision`.

Guard contract (`core/registry.py`): a class decorated with `@register_guard("<yaml type>")`, with `Params` subclassing `CommonParams` (pydantic, `extra="forbid"`), `requires: frozenset` of `"chat"` and/or `"embedder"`, and `__init__(params, deps: GuardDeps)`. Built-in guards in `core/guards/` register themselves when `core/__init__.py` imports them. Files referenced from YAML resolve relative to the YAML's directory via `deps.read_text` / `deps.read_lines`. A non-empty `requires` marks a network guard, and four behaviours depend on it: the default 10 s timeout, auto-creating an `OpenRouterClient` for client kinds the caller did not pass, the `network_calls` metric, and which guards get a threshold sweep in eval.

Score convention, relied on by eval: `GuardResult.score` is a violation score in 0..1 (higher means worse) and must be set on every successful check, including `allow`. Rule guards return 1.0 or 0.0. When a guard raises or times out, the pipeline (not the guard) builds the result: `score=None`, `category=None`, text unchanged, and action taken from `on_error` (default `block`, fail closed). Logs carry only the guard name and exception class, never the checked text.

Eval: `eval/runner.py` runs either the full pipeline per sample (`run_pipeline`) or each guard alone via `Guardrail.only(stage, name)` (`run_isolate`), because short-circuiting hides how accurate later guards are. Guards are keyed `"<stage>/<name>"` since names are unique only per stage. `eval/metrics.py` is pure functions over `Record`s. "Positive" means expected (or predicted) is not `allow`. Rates are `None` when the denominator is zero. `eval/report.py` writes `records.jsonl`, `summary.json`, `summary.md` and a config copy into a new `_workspace/runs/<timestamp>/` directory, refusing to overwrite. `compare` refuses runs of different modes.

## Conventions

- `core/constants.py`: the code between each `# <TAG>:BEGIN` / `# <TAG>:END` pair in `ModelId` is generated by `scripts/sync_models.sh`, so never edit it by hand. All three marker pairs (`OPENROUTER`, `OPENROUTER-EMBED`, `OPENROUTER-RERANK`) must stay, or the script fails. YAML model ids are plain strings and are not validated against `ModelId`.
- Tests never hit the network. Use `FakeChatClient` / `FakeEmbedder` from `tests/fakes.py` or `httpx.MockTransport`. Async code is driven with `asyncio.run` (pytest-asyncio is not installed). Tests may register throwaway guard types with `register_guard("test_...")`.
- `datasets/public/` is gitignored because `lmsys/toxic-chat` is CC-BY-NC-4.0 (internal benchmarking only). `datasets/sample.jsonl` is the committed hand-labelled set. Dataset rows are validated by `eval/dataset.py` (`extra="forbid"`, unique ids).
